# MTT user_edid.bin

Fixed EDID 1.3 (128 bytes) for OpenDisplay MTT CustomEdid.

## Per-iPad EDID (runtime)
The app generates the EDID **per iPad from its hello size** when a session
starts, before the MTT head attaches (`MttModesForHello` + `BuildMttEdid` in
`src/display/MttVddSettings.cpp`). If the generated bytes / XML modes differ
from `C:\VirtualDisplayDriver\`, it shows a one-time tray notice and asks for
admin once (`--ensure-mtt-edid WxH`) to write them and reload MttVDD. The same
iPad reconnecting is a no-op (no prompt, no reload). If the prompt is declined
the session still connects with whatever EDID is installed.

This file is the **shipped fallback** (11" default, hello 2360x1640), copied
next to the exe by the post-build step and used when no hello size is known or
nothing is installed yet.

## Identity (stable - do not randomize)
- Manufacturer: MTT
- Product: 0x1337
- Serial: 0x4F445731 ("ODW1")

Same identity for every iPad size, so Windows keeps it the same monitor and the
saved arrangement still applies.

## Mode rule (landscape, 16-px floor aligned, @ 60 Hz, max 4 DTDs)
1. Native hello size, long side first (preferred)
2. Closest-aspect sibling iPad panel (aspect within 1%, width within 8%)
3. 3/4 of native
4. 1/2 of native

Unused DTD slots carry a monitor-name ("OpenDisplay") / dummy descriptor.
For 2360x1640 this gives the shipped file: 2352x1632, 2384x1664, 1760x1216, 1168x816.

## Generate / check
```
python tools/gen_user_edid.py                      # shipped fallback -> assets/mtt/user_edid.bin
python tools/gen_user_edid.py --size 2752x2064 -o x.bin
python tools/gen_user_edid.py --size 2752x2064 --modes
python tools/gen_user_edid.py --decode assets/mtt/user_edid.bin
```
The Python generator is the reference implementation; the app's bytes must
match it. To compare: `opendisplay-win --dump-mtt-edid WxH out.bin`.

## Manual install (normally done by the app)
1. Copy bin to `C:\VirtualDisplayDriver\user_edid.bin`
2. Set `<CustomEdid>true</CustomEdid>` and `<PreventSpoof>true</PreventSpoof>` in `vdd_settings.xml`
3. Keep XML `<resolutions>` mirrored to the same modes, same order (IddCx QueryTargetModes still reads XML; CustomEdid alone does not emulate modes)
4. Reload MttVDD (`pnputil /restart-device` on Root\MttVDD, or run `opendisplay-win --ensure-mtt-edid [WxH]` elevated)
